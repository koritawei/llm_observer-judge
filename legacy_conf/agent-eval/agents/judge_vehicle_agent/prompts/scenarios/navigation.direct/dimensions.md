## 场景专属规则

本节只描述 `navigation.direct` 相对全局 D0-D6 与 `navigation` 场景族规则的专属覆盖；未覆盖项回退到公共规则。

### 场景专属硬条件

- D4: 必须满足当前预期输出形态；预期导航执行但 `cmd_list` 为空，按 D4 执行闭环失败处理。
- D1: 未识别为导航/改路/路线问询任务，或将导航与搜索、普通问询混淆，按 D1 失败处理。
- D1: 起点、终点、途经点、路线策略、道路限制、空间约束或顺序关系的用户意图识别错误，按 D1 归因。
- D2: 起点、终点、途经点、路线策略、道路限制、空间约束或顺序关系未被正确满足，按 D2 归因；导致导航对象不可用时判 0 分。
- D4: 途经点与终点混淆、途经点顺序错误、终点丢失，按 D4 归因；导致路线不可用时判 0 分。
- D4: 原路线被错误覆盖，按 D4 归因；导致路线不可用时判 0 分。
- D3: 总结文本声称已采纳某路线策略，但 `cmd_list` 或 `tool_calls` 中无对应参数支撑，按 D3 归因。
- D5: Markdown 缺失或无法确认执行对象时，若影响用户确认导航对象，按 D5 归因。
- D5: 总结文本声称已采纳某路线策略但证据不足，且未披露相关限制，按 D5 归因。

### 专属维度覆盖

- D1：这是导航直接执行类场景，重点看是否正确识别为导航执行意图，并区分路线规划、改路、搜索和普通问询；还需识别核心目的地、动作意图、途经点和多轮指代。
- D2：重点看起点、终点、途经点、途经点顺序、空间约束、路线策略和道路限制是否被正确传入并满足；多个策略需同时生效，例如“不走三环”“走五环”“红绿灯最少”“躲避拥堵”。
- D3：重点看目的地、路线信息、POI 标签、已采纳策略是否有 `cmd_list`、`tool_calls`、`env` 或 `history` 证据；不得声称已采纳未实际传入的路线策略。
- D4：重点看是否按当前预期输出形态产出唯一、可执行、动作类型正确的导航 CMD；字段错误、漏发、误发优先归因 D4。
- D5：总结文本应简洁确认已采纳的目的地、途经点、规避/偏好策略，帮助用户确认导航对象和关键策略；表达误导错误路线时可判 0 分。
- D6：纯导航执行类不要求主动补充距离、耗时、评分等信息；只有存在选择、比较、澄清或关键限制时才适用。
