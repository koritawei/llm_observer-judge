## 场景专属规则

本节只描述 `multi-turn.s8` 相对通用前置规则与全局 D0-D6 规则的补充项；未覆盖项按公共规则判断。评估时只评估当前 `{{turn_index}}` 对应轮次，但必须结合 `{{history}}` 理解上下文、指代对象和历史约束。

### 各轮预期输出形态

- Q1: Markdown=是 / CMD=否
- Q2: Markdown=是 / CMD=否
- Q3: Markdown=是 / CMD=否
- Q4: Markdown=是 / CMD=是

### 轮次快速检查表

本表用于先定位当前 `{{turn_index}}` 的核心任务；具体扣分归因按全局 D0-D6 和本场景专属规则执行。

- Q1：识别“车有点脏了啊”的洗车隐含意图，推荐附近洗车店，CMD=否。
- Q2：继承 Q1 推荐列表中的第一家洗车店，回答评价，事实来自工具或已提供上下文，CMD=否。
- Q3：继承同一洗车店，回答优惠/折扣；无证据需如实说明，不得编造优惠信息，CMD=否。
- Q4：确认前往该洗车店，生成 1 条导航 CMD，CMD=是。

### 场景专属硬条件

- D4: 必须同时满足当前 `{{turn_index}}` 的预期输出形态；Q1-Q3 必须输出 Markdown 且 `cmd_list` 为空，Q4 必须输出 Markdown 且生成 1 条导航 CMD。
- D4: Q1-Q3 任一轮误发 CMD、Q4 应发 CMD 但 `cmd_list` 为空、或 `cmd_list` 中出现 2 条或更多端指令，按 D4 失败处理；其中端指令冲突或当前轮输出形态完全不符时，最终判 0 分。
- D1: 当前轮次主意图错误，无法从 `history` 解析“第一家/这家/那就去吧”等指代，或把评价/优惠问询误判为导航、把 Q4 确认前往误判为普通问询，按 D1 失败处理。
- D2: 历史继承失败导致使用错误洗车店、丢失被确认对象、凭空指定对象，或把旧约束错误套用到当前轮次导致任务不可用，按 D2 失败处理。
- D3: 编造评价、优惠券、折扣、POI 属性或导航目标，或总结文本、POI 标签、CMD 目标与工具返回或 `history` 明显矛盾，按 D3 失败处理。

### 专属维度覆盖

- D1：Q1 需识别“车有点脏了啊”的隐含意图是洗车并推荐洗车店；Q2 需将“第一家”解析为 Q1 推荐列表中的第一家洗车店；Q3 需继承上下文中的同一洗车店并理解为优惠/折扣问询；Q4 需理解“那就去吧”为确认前往该洗车店。
- D2：Q2/Q3 应继承 Q1 的洗车店候选或已选洗车店，但不应新增无关目的地或误发导航 CMD；Q4 应把历史中被用户确认的洗车店转化为当前轮次的导航目标。若 `history` 中没有足够证据确定指代对象，应说明无法确认或发起澄清，不能凭空指定对象。
- D3：Q2 的评价信息必须来自工具返回或历史中可验证的信息；Q3 的优惠券/折扣信息必须有工具或上下文支撑，若无法获取需如实说明，不得编造优惠信息；Q4 的导航终点必须是历史中被确认的同一洗车店。
- D4：CMD 是否输出、缺失、误发或冲突只以 `{{cmd_list}}` 为准；Q1-Q3 不误发 CMD，Q4 只发 1 条正确导航 CMD，终点与历史确认对象一致。
- D5：Q1 应表达洗车店推荐；Q2 应清楚回答第一家洗车店评价；Q3 应清楚回答优惠/折扣信息或如实说明无法获取；Q4 应明确表达即将出发前往该洗车店。纯信息问询不得用容易误导为导航执行的话术。
- D6：Q1 推荐洗车店列表时，应在工具返回支持范围内提供足够候选信息；Q2 应提供能帮助判断洗车店质量的评价信息；Q3 应明确优惠/折扣是否可得或无法获取；Q4 是确认导航的执行轮次，简洁确认目的地即可，不应因未主动补充距离、耗时、评分等信息而扣分。
