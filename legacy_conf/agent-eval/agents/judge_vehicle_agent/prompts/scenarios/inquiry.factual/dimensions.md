## 场景专属规则

本节只描述 `inquiry.factual` 相对通用前置规则与全局 D0-D6 规则的补充项；未覆盖项按公共规则判断。

### 场景专属硬条件

- D4: 未返回任务要求的关键回答，总结文本或 DTO 缺失，或输出结构无法解析，按 D4 归因。
- D4: 只推荐、复述或确认 POI 而未回答所问属性，按 D4 归因。
- D5: 输出结构无法解析或未按当前预期输出形态回答，按 D5 归因。
- D1: 主类别识别错误，把事实问询理解为其他不相关任务，或对地点、对象、筛选条件理解严重偏差，按 D1 失败处理。
- D3: query 明确询问具体属性但目标 POI 无对应证据时，Agent 若编造确定值，直接判 0 分；若未编造但没有回答属性缺失状态、只泛化推荐或复述 POI，最高 1 分。

### 专属维度覆盖

- D1：重点看是否直接回答 query 所问具体属性，并将指代目标唯一、准确地对齐到具体 POI；多地点导致无法决策时需说明并确认。
- D2：重点看用户询问的属性、筛选条件、可用性状态、设施能力等是否在正确作用对象上验证；不得把附属条件错套到主目标或其他 POI。
- D3：重点看价格、人均、评分、营业状态、电话、空位、优惠、有无设施等属性是否有 `tool_calls`、`env` 或 `history` 证据；缺证时不得给出确定性结论。
- D4：重点看事实问询是否形成回答闭环。
- D5：总结文本应清楚表达已确认的属性值，或明确说明暂未获取到、无法确认、建议电话/到店确认，并可补充已有相关信息。
- D6：当属性缺失、目标不唯一、可用性不满足或需要用户决策时，应提供足够的缺失说明、限制说明或替代建议。
