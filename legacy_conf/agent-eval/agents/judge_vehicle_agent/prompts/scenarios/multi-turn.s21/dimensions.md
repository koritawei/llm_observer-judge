## 场景专属规则

本节只描述 `multi-turn.s21` 相对通用前置规则与全局 D0-D6 规则的补充项；未覆盖项按公共规则判断。

### 各轮预期输出形态

- Q1: Markdown=是 / CMD=是
- Q2: Markdown=是 / CMD=是

### 轮次快速检查表

Q1：正确识别“开到上海虹桥机场”为路线终点，理解“路上每隔200公里充一次电”为长途路线规划中的沿途充电间隔约束；CMD 应发起到上海虹桥机场的路线规划，并在路线或途经点选择中体现约每 200 公里补能一次的约束。
Q2：理解“这个充电太密了”为对 Q1 充电方案的负反馈，“改成每300公里充一次电”为修改沿途充电间隔并重新规划路线的意图；需继承 Q1 的终点上海虹桥机场和长途自驾场景，将充电间隔从 200 公里更新为 300 公里，CMD 应重新规划或更新路线。

### 场景专属硬条件

- D4: 必须满足当前轮次（{{turn_index}}）在“各轮预期输出形态”中的预期输出形态；该输出 CMD 却 `cmd_list` 为空、或不该输出 CMD 却 `cmd_list` 非空，按 D4 归因。
- D1: 当前轮次主意图识别错误，或将长途路线规划、沿途补能规划、参数修改、改路等任务类型混淆，按 D1 失败处理。
- D1: Q1 必须把“上海虹桥机场”识别为终点，并把“每隔200公里充一次电”识别为沿途补能间隔约束；遗漏终点、遗漏充电约束或把 200 公里理解成总里程/绕行距离，按 D1 归因。
- D2: Q2 必须继承 Q1 的终点和路线状态，只修改充电间隔为“每300公里充一次电”；若仍按 200 公里规划或丢失上海虹桥机场，按 D2 归因。
- D4: Q2 误改为搜索单个充电站或仅文本解释不更新路线，导致未形成路线更新的执行闭环，按 D4 归因。
- D1: 多轮指代对象错误，例如“这个充电太密了”未正确指向 Q1 的沿途充电方案，按 D1 归因。
- D3: 多轮指代对象错误导致引用的历史充电方案与实际不符，按 D3 归因，导致执行对象不可用 判 0 分。

### 专属维度覆盖

- D1：重点看是否正确理解长途自驾到上海虹桥机场、沿途补能规划，以及 Q2 对“充电太密”的参数修改意图。
- D2：重点看终点、路线状态和充电间隔约束是否跨轮继承；Q1 为约 200 公里补能一次，Q2 必须更新为约 300 公里补能一次，不能同时保留旧约束。
- D3：重点看 总结文本、路线变化、途经充电点或充电策略说明是否有 `env` 或 `tool_calls` 证据支撑，不得凭空承诺间隔补能。
- D4：重点看 Q1、Q2 都应形成可执行路线闭环；Q2 不是单纯问询或搜索展示，而是带新充电间隔的路线更新/重规划。
- D5：总结文本 应明确说明当前采用的充电间隔、目的地和路线调整结果，避免用户无法判断是否已从 200 公里改为 300 公里。
- D6：仅在充电站不可达、间隔无法严格满足、续航/路线数据不足或需要用户确认备选方案时适用；正常可执行规划不要求额外补充未询问的信息。
