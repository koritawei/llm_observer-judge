## 场景专属规则

本节只描述 `search.single-poi-compound` 相对通用前置规则与全局 D0-D6 规则的补充项；未覆盖项按公共规则判断。

### 场景专属硬条件

- D4: 必须满足当前预期输出形态；工具存在满足主品类及核心约束的有效候选却未输出对应 DTO，搜索未闭环，判 0 分；工具经针对性搜索仍无有效候选，且 Agent 明确披露无结果并给出合理拒答或兜底时，DTO 可为空，D4 判 2 分。`cmd_list` 非空时，由评判者结合用户意图判断 CMD 是否合理：发 CMD 是对 query 意图的合理兑现（如"快没油了"→发起导航去加油站）则不视为误发；用户意图仅为搜索/推荐候选却发起导航等端指令（如"找个附近评分高的川菜馆"→直接导航到某一家），属于误发端指令，按 D4 归因。
- D1: query 形如“含 A 和 B 的某场所”时，若未识别父级 POI、遗漏任一子 POI，按 D1 归因；组合关系整体失败时判 0 分。
- D2: query 形如“含 A 和 B 的某场所”时，若把内部子 POI 当作主召回对象，按 D2 归因；组合关系整体失败时判 0 分。
- D2: 父级 POI 与全部子 POI 的包含关系、地理范围、附近/周边语义、可用性状态或关键约束明显错误，按 D2 归因；导致推荐结果不可用时判 0 分。

### 专属维度覆盖

- D1：重点看是否识别父级 POI 与多个子 POI 的组合关系，并区分“找父级场所”与“找内部设施/门店”。
- D2：重点看父级 POI 是否真实包含 query 指定的全部子 POI，且地理范围、可用性和其他筛选条件同时生效。
- D3：重点看父级名称、子 POI 名称、地址、标签、距离、状态和包含关系是否有 `tool_calls`、`env` 或 `history` 证据。
- D4：重点看搜索是否形成与候选状态一致的闭环：存在有效候选时应输出对应 DTO；无有效候选且已明确披露并合理拒答时允许 DTO 为空。CMD 是否适当结合用户意图判断。
- D5：总结文本应清楚表达“为您找到同时包含 A 和 B 的父级场所”这类组合关系，避免让用户误解召回对象。
- D6：当组合关系证据不足、只满足部分子 POI、结果不可用或需要用户选择时，应提供必要说明或替代建议。
