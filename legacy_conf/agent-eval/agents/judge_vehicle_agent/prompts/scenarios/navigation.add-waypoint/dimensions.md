## 场景专属规则

本节只描述 `navigation.add-waypoint` 相对通用前置规则与全局 D0-D6 规则的补充项；未覆盖项按公共规则判断。

### 场景专属硬条件

- D4: 必须满足当前预期输出形态；预期添加途经点但 `cmd_list` 为空，按 D4 执行闭环失败处理。
- D1: 未识别为添加途经点意图，或将“添加途经点”误处理为重新发起导航、更改终点、普通搜索或路线问询，按 D1 失败处理。
- D2: 新增途经点 POI 与 query 意图不匹配，按 D2 归因；导致路线不可用时判 0 分。判定是否匹配不得只看 POI 名称字面：途经点来自以 query 中地点词为关键词的 search_place 调用时，搜索本身就是意图匹配过程，POI 名称不含关键词字样（如关键词“万象城停车场”返回名为“停车场”的 POI）不构成不匹配证据，需结合详细地址、商圈及与所指实体的空间关系综合判断；仅存在确凿反证（如不同城市的同名实体、明显不同实体且存在更匹配候选）时才可判不匹配。
- D2: 添加途经点分两类判定：用户点名实体（query 给出明确地点名，如“添加XX停车场为途经点”）时 agent 无候选选择权，以该实体为关键词搜索并采纳搜索结果即为匹配，不评偏离主路线/绕行距离；用户仅给出类别（如“前面找个服务区”）由 agent 自主选择途经点时，须基于当前导航路线前方及合理偏移范围搜索，反而使用用户当前位置周边或目的地附近的，按 D2 归因，明显偏离主路线时判 0 分。
- D4: 把新增途经点误作终点、删除/覆盖原终点、错误调整途经点顺序，按 D4 归因；导致路线不可用时判 0 分。
- D2: 添加途经点时未基于当前导航路线前方及合理偏移范围搜索，反而使用用户当前位置周边或目的地附近，按 D2 归因；明显偏离主路线时判 0 分。仅适用于 agent 自主选择途经点的场景，用户点名实体的判定边界见上一条。
- D3: 总结文本声称已添加某途经点或保留原终点，但 `cmd_list`、`tool_calls` 或 `history` 无对应支撑，按 D3 归因。
- D5: Markdown 缺失或无法确认新增途经点，或总结文本声称已添加但证据不足且未披露限制，按 D5 归因。

### 专属维度覆盖

- D1：重点看是否正确区分添加途经点、更改终点、调整途经点/终点顺序、重新发起导航、普通搜索和路线问询，并识别用户要新增的途经点对象。
- D2：重点看是否保持原终点不变、是否满足 query 中的类别、品牌、设施、路线偏好等约束；用户点名实体时只需确认采纳 POI 来自对应关键词搜索（判定边界见硬条件），不评路线偏移；agent 自选途经点时才评估是否位于当前导航路径前方及合理偏移范围内。
- D3：重点看新增途经点、原终点保留、路线变更说明、POI 标签和已采纳策略是否有 `cmd_list`、`tool_calls`、`env` 或 `history` 证据。
- D4：重点看是否产出唯一、可执行、动作类型正确且包含新增途经点的 CMD；字段错误、漏发、误发或错误覆盖原路线优先归因 D4。
- D5：总结文本应简洁确认新增了哪个途经点、终点是否变化以及关键路线策略，帮助用户确认路线变更；表达误导错误路线时可判 0 分。途经点 POI 名称本身不含用户指定地点词时（如关键词“万象城停车场”返回名为“停车场”的 POI），agent 按工具返回的实际名称播报即视为已确认新增了哪个途经点，不因未复述用户指定地点词而判关键说明不足；主动补充空间关系（如“万象城附近”）属增强表达，不是必需。
- D6：纯添加途经点执行类不要求主动补充距离、耗时、评分等信息；只有存在选择、比较、澄清、绕行过大或不可用限制时才适用。
