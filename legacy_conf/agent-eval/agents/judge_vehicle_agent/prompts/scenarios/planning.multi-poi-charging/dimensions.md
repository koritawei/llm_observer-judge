## 场景专属规则

本节只描述 `planning.multi-poi-charging` 相对通用前置规则与全局 D0-D6 规则的补充项；未覆盖项按公共规则判断。

### 场景专属硬条件

- D4: 必须满足当前预期输出形态；预期充电规划执行但 `cmd_list` 为空，按 D4 执行闭环失败处理。
- D4: Markdown 缺失或无法确认充电规划逻辑时，若影响执行闭环确认，按 D4 归因。
- D1: 未识别为长途/多点充电规划，或遗漏充电节奏、服务区、品牌偏好、用餐时间等核心规划目标，按 D1 归因。
- D2: 充电节奏、服务区、品牌/超充偏好、用餐时间、停靠顺序或充电次数等明确约束均已落实到每个适用充电节点时，D2 才可判 2 分；任一明确约束未完全满足但路线仍可用，即使已披露限制或提供合理替代，D2 也只能判 1 分。
- D2: 用户明确要求每隔 N 小时或 N 公里充电时，必须按相邻充电节点核验实际间隔，不得使用累计到达耗时。实际间隔相对 N 的偏差不超过 20% 可视为满足；偏差超过 20% 但未造成续航风险，判 1 分；偏差造成续航断点或规划不可用，判 0 分。
- D2: 全部候选中无满足品牌、超充、服务区或用餐时间要求的充电站时，选用替代节点并明确披露未满足项，路线仍可用则判 1 分；不得因替代方案合理或说明充分而判 2 分。
- D2: 充电停靠点身份、实际行驶顺序、相邻间距或路线逻辑错误，导致续航断点或整体规划不可用时判 0 分。多个已明确披露的合理替代节点不因数量达到 2 个而直接判 0 分；只有多个节点的身份、顺序或路线逻辑错误使整体行程不可靠时才判 0 分。
- D3: 时间字段必须区分以下口径：`累计到达耗时`是从起点到当前节点的总行驶耗时；`分段行驶耗时`是两个相邻路线节点之间的行驶耗时；`相邻充电间隔`对第一个充电点是起点至该点的分段行驶耗时，对后续充电点是前一个充电点至当前充电点的分段行驶耗时。工具已直接返回分段值时优先使用；只有同一条路线、同一单位且同一累计口径的值才允许用“当前节点累计耗时减去前一充电节点累计耗时”计算相邻充电间隔。除非工具明确计入停留时间，否则充电/休息停留时长不得混入行驶间隔。
- D3: 派生时间必须先按原始精度完成差值或求和，再统一换算和四舍五入。例如前一充电点累计耗时为 2 小时 7 分、当前充电点累计耗时为 3 小时 58 分，则相邻充电间隔为 1 小时 51 分，可表述为“约 2 小时”；不得直接把当前累计耗时表述为“间隔约 4 小时”。证据 coverage 为 `partial/truncated` 且缺失分段可能影响计算时不得自行补值；若仍输出缺少证据支撑的确定性时间结论，按 D3 事实虚构判 0 分。
- D5: 存在未满足约束或替代节点时，总结文本必须准确说明未满足项及替代关系；未披露限制或替代关系说明不清，导致用户误解规划结果时，按 D5 归因。若将未满足的约束声称为已满足，按 D3 事实虚构处理。
- D6: 存在无理想桩、时间无法精确匹配、充电站临时不可用、绕行偏大或续航风险时，必须提供足够的限制说明、替代依据和风险信息；信息缺失导致用户无法判断规划是否可用时判 0 分，其余明显缺失判 1 分。

### 专属维度覆盖

- D1：重点看是否正确识别充电规划意图，并拆解充电节奏、服务区要求、品牌/超充偏好、用餐时间、全程次数等子目标。
- D2：重点看充电停靠点是否按实际行驶顺序排列，是否位于服务区或合理沿途范围，是否避免续航断点；用户限定间隔时按相邻充电节点核验，偏差不超过 20% 可视为满足；未限定间距时，途经点充电站间距应在 200km 左右，不能过近。
- D3：重点核对充电站身份、服务区属性、品牌/超充能力、时间匹配、替代方案和 POI 标签是否有 `cmd_list`、`tool_calls`、`env`、`env` 或 `history` 证据；涉及时间时必须先辨明累计到达耗时、分段行驶耗时和相邻充电间隔，再核对节点对象、路线顺序、单位与计算口径。
- D4：重点看是否产出唯一、可执行、动作类型正确且包含多个充电途经点的 CMD；字段错误、漏发、误发或节点顺序错误优先归因 D4。
- D5：总结文本应还原充电规划逻辑，明确节奏、关键约束、停靠顺序和必要替代说明，便于用户确认。
- D6：存在无理想桩、无法精确匹配用餐时间、充电站不可用、绕行过大或续航风险时，应提供必要限制说明或替代方案；纯执行成功时不要求额外冗余信息。
