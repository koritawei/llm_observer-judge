## 场景专属规则

本节只描述 `search.with-category` 相对通用前置规则与全局 D0-D6 规则的补充项；未覆盖项按公共规则判断。

### 场景专属硬条件

- D4: 必须满足当前预期输出形态；工具存在满足主品类及核心约束的有效候选却未输出对应 DTO，搜索未闭环，判 0 分；工具经针对性搜索仍无有效候选，且 Agent 明确披露无结果并给出合理拒答或兜底时，DTO 可为空，D4 判 2 分。`cmd_list` 非空时，由评判者结合用户意图判断 CMD 是否合理：发 CMD 是对 query 意图的合理兑现（如"快没油了"→发起导航去加油站）则不视为误发；用户意图仅为搜索/推荐候选却发起导航等端指令（如"找个附近评分高的川菜馆"→直接导航到某一家），属于误发端指令，按 D4 归因。
- D1: query 已明确 POI 类别时，若召回结果跨类别替换、主类别识别错误或任务类型混淆，按 D1 失败处理。
- D2: 地理范围、附近/周边语义、明确类别、时间/场景隐含条件、可用性状态或关键筛选条件明显错误，按 D2 归因；导致推荐结果不可用时判 0 分。

### 专属维度覆盖

- D1：重点看是否严格识别用户明确给出的 POI 类别，不得用相近但不同的类别替换。
- D2：重点看明确类别、地理范围、附近/周边语义、时间/场景隐含条件、可用性和排序偏好是否同时生效。
- D3：重点看 POI 名称、地址、标签、营业/可用状态、价格/评分等事实是否有 `tool_calls`、`env` 或 `history` 证据；不得虚构标签或属性。
- D4：重点看搜索是否形成与候选状态一致的闭环：存在有效候选时应输出对应 DTO；无有效候选且已明确披露并合理拒答时允许 DTO 为空。CMD 是否适当结合用户意图判断。
- D5：总结文本应围绕明确类别和关键条件说明推荐结果，避免答非所问或表达成已执行导航。
- D6：当明确类别下结果不足、条件冲突、不可用或需要用户选择时，应提供必要说明或替代建议。
