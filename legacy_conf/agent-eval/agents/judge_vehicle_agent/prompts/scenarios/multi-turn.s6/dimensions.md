## 场景专属规则

本节只描述 `multi-turn.s6` 相对通用前置规则与全局 D0-D6 规则的补充项；未覆盖项按公共规则判断。

### 各轮预期输出形态

- Q1: Markdown=是 / CMD=是
- Q2: Markdown=是 / CMD=是
- Q3: Markdown=是 / CMD=否
- Q4: Markdown=是 / CMD=否

### 轮次快速检查表

Q1：正确识别"导航去首都机场"中的"首都机场"为终点，CMD 正确发起导航，summary 与目的地强相关。
Q2：理解"不对我说错了，是大兴机场，换一下"为用户纠正目的地的意图，将终点从首都机场替换为"大兴机场"，CMD 正确更新终点。
Q3：理解"从这走要多久到？"为路线信息问询，返回从当前位置到大兴机场的预计行驶时间，数据须来自工具返回，不得编造。本轮不应发出导航 CMD。
Q4：理解"那边有适合接待朋友的餐厅吗"中的"那边"指代大兴机场（当前终点），在大兴机场附近搜索适合接待朋友的餐厅，summary 体现餐厅推荐且与接待场景相关。

### 场景专属硬条件

- D4: 必须满足当前轮次（{{turn_index}}）在“各轮预期输出形态”中的预期输出形态；该输出 CMD 却 `cmd_list` 为空、或不该输出 CMD 却 `cmd_list` 非空，按 D4 归因。
- D1: 当前轮次主意图识别错误，或将导航、改路、搜索、问询、属性追问等任务类型混淆，按 D1 失败处理。
- D2: 当前轮次的地点范围、筛选条件、路线策略、终点/途经点关系或属性问询对象继承错误，按 D2 归因；破坏当前任务闭环时判 0 分。

### 专属维度覆盖

- D1：重点看当前轮次是否继承正确的历史目标、候选列表、路线状态和用户修正意图，并区分搜索、问询、导航、改路和属性追问。
- D2：重点看跨轮叠加条件是否持续生效，例如距离、价格、评分、营业状态、路线策略、终点附近、沿途、途经点顺序等。
- D3：重点看总结文本、POI 标签、属性回答、路线变化和 CMD 对象是否有 `history`、`tool_calls`、`env` 或 `cmd_list` 证据。
- D4：重点看当前轮次是否按“各轮预期输出形态”执行或避免执行 CMD；多轮改路、选中候选、更新终点时必须形成唯一可执行闭环。
- D5：总结文本应明确承接历史上下文，说明本轮筛选、回答或路线变更结果，避免让用户无法确认指代对象。
- D6：仅在当前轮次存在选择、比较、澄清、属性缺失、不可用状态或关键限制时适用；纯执行轮次不要求额外补充未询问的信息。
