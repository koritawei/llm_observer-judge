## 场景专属规则

本节只描述 `planning.multi-poi-route` 相对通用前置规则与全局 D0-D6 规则的补充项；未覆盖项按公共规则判断。

### 场景专属硬条件

- D1: 涉及家、公司、当前位置、历史地点等锚点时，需结合 `env` 或 `history` 正确解析指代；误把锚点当作无关地点或本轮新约束，按 D1 归因。
- D1: 未识别为多点路线规划，或将中间停靠点、终点、接人/办事/消费等不同目的混淆，按 D1 归因。
- D1: 起点、中间停靠点、终点、途经点顺序或路线策略的用户意图识别错误，按 D1 归因；导致行程不可用时判 0 分。
- D2: 起点、中间停靠点、终点、途经点顺序或路线策略未被正确满足，按 D2 归因；导致行程不可用时判 0 分。
- D2: 多点序列中 ≥ 2 个节点出现 POI 身份错误、途经点顺序错误、子约束未满足或路线逻辑断裂，直接判 0 分。
- D4: 必须满足当前预期输出形态；预期多点规划执行但 `cmd_list` 为空，按 D4 执行闭环失败处理。
- D4: CMD 必须覆盖所有必要途经点、终点和导航动作；CMD 途经点顺序、summary 描述和最终路线不一致时，按 D4 归因。
- D5: Markdown 缺失，或总结文本未清晰说明必要途经点、终点、顺序及关键路线策略，导致用户无法确认完整行程时，按 D5 归因；默认起点及可由地点名称或上下文明确推知的停靠目的，无需重复说明。

### 专属维度覆盖

- D1：重点看是否正确识别多点路线规划意图，并将昵称、俗称、场景化描述映射到真实 POI；存在歧义时应在表达中说明或选择最可能对象。
- D2：重点看每个节点的 POI 身份、先后顺序、显性条件和合理隐性需求是否满足；多个节点和策略需同时生效。
- D3：重点看完整行程逻辑、节点约束、动态状态、POI 标签和已采纳策略是否有 `cmd_list`、`tool_calls` 或 `history` 证据；不得给出无依据的确定性断言。
- D4：重点看是否产出唯一、可执行、动作类型正确且包含起终点和途经点顺序的多点导航 CMD；字段错误、漏发、误发或错误覆盖路线优先归因 D4。
- D5：总结文本应还原完整行程逻辑：起点 → 中间停靠点 → 终点，并说明关键停靠目的和策略，便于用户确认。
- D6：纯多点规划执行类不要求主动补充距离、耗时、评分等信息；涉及动态状态、不可用限制、歧义或替代方案时才适用。
