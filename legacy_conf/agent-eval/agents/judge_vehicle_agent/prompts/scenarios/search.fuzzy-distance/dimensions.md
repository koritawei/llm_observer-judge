## 场景专属规则

本节只描述 `search.fuzzy-distance` 相对通用前置规则与全局 D0-D6 规则的补充项；未覆盖项按公共规则判断。

### 场景专属硬条件

- D4: 必须满足当前预期输出形态；工具存在满足主品类及核心约束的有效候选却未输出对应 DTO，搜索未闭环，判 0 分；工具经针对性搜索仍无有效候选，且 Agent 明确披露无结果并给出合理拒答或兜底时，DTO 可为空，D4 判 2 分。`cmd_list` 非空时，由评判者结合用户意图判断 CMD 是否合理：发 CMD 是对 query 意图的合理兑现（如"快没油了"→发起导航去加油站）则不视为误发；用户意图仅为搜索/推荐候选却发起导航等端指令（如"找个附近评分高的川菜馆"→直接导航到某一家），属于误发端指令，按 D4 归因。
- D1: 模糊、描述性限定条件（如“浪漫约会”“氛围好”“视野好”）未作为硬性筛选条件，或主类别、地点、对象识别严重偏差，按 D1 归因。
- D2: 模糊、描述性限定条件未作为硬性筛选条件作用到推荐结果，按 D2 归因。
- D2: 地理范围、附近/周边语义、唯一目标判断、可用性状态或关键约束明显错误，按 D2 归因；导致推荐结果不可用时判 0 分。

### 专属维度覆盖

- D1：重点看是否正确识别模糊/描述性需求，并将其作为硬性筛选条件；当 query 指向唯一目标时应识别为唯一需求而非模糊列表需求。
- D2：重点看氛围、环境、特色服务/设施、视野景观等描述性属性是否作用到每个推荐 POI；唯一目标类 query 应返回单一高置信度结果。
- D3：重点看 POI 名称、地址、标签、距离、可用状态和推荐理由是否有 `tool_calls`、`env` 或 `history` 证据。
- D4：重点看搜索是否形成与候选状态一致的闭环：存在有效候选时应输出对应 DTO；无有效候选且已明确披露并合理拒答时允许 DTO 为空。CMD 是否适当结合用户意图判断。
- D5：总结文本应说明推荐结果与模糊需求的匹配关系，避免泛化推荐或表达成已执行导航。
- D6：当模糊条件无法验证、唯一目标不确定、结果不足、不可用或需要用户选择时，应提供必要说明或替代建议。
