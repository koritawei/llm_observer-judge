## 场景专属规则

本节只描述 `route-inquiry.along-route` 相对通用前置规则与全局 D0-D6 规则的补充项；未覆盖项按公共规则判断。

### 场景专属硬条件

- D4: 以 `env` 判断是否已有当前路线：`env` 明确展示当前导航路线时，查询该路线的 ETA、距离、费用、拥堵、道路属性或沿途信息不应发新路线 CMD；`env` 为空或未展示当前导航路线时，若回答 query 必须先计算一条明确新路线，则应有路线计算 CMD。已有路线下出现明确不同目的地，或 query 与当前路线的关系无法从 `env`、query、`tool_calls` 确认时，按证据综合判断，不套用静态结论。`history` 仅用于解释 query 指代，不能推翻 `env` 的路线状态。违反上述要求按 D4 归因。
- D5: 预期路线问询回答但缺少关键总结文本，按 D5 归因。
- D1: 判定「未识别为基于当前生效路线的沿途问询」或「将沿途问询误处理为改路、搜索、导航执行」时，必须综合 `tool_calls`、`cmd_list`、`env` 与回答内容的行为证据认定，不得仅凭 intent 标签或 `<recommend>`/DTO 输出形态定罪，仅当实际按普通周边搜索处理、未基于当前路线作答、发起改路/导航 CMD，或回答内容偏离所问沿途属性时，按 D1 失败处理。
- D2: 沿途对象类型、数量、位置、距离、收费、服务区/收费站/电子眼等路线属性回答错误，或未基于当前导航/规划路线作答，或把目的地附近、当前位置附近与沿途对象混淆，按 D2 归因；导致答案不可用时判 0 分。
- D3: 沿途对象类型、数量、位置、距离、收费、服务区/收费站/电子眼等路线属性回答错误，与证据不一致，按 D3 归因。

### 专属维度覆盖

- D1：重点看是否识别为路线沿途信息问询，并正确解析用户询问的沿途对象和属性维度；不得误判为路线修改或新增导航。识别与否以工具链路等行为证据为准，调用沿途搜索类工具并基于当前路线作答即视为已识别；intent 标签仅作辅助证据，标签与场景名不一致不构成失败。
- D2：重点看回答是否基于当前生效路线，并区分沿途、当前位置附近、终点附近等空间语义；对象类型和属性维度需与 query 对齐。
- D3：重点看沿途对象、数量、距离、费用、交通设施、行驶建议等信息是否有 `tool_calls`、`env`、`history` 或 `cmd_list`  证据。
- D4：重点看路线问询是否形成回答闭环；以 `env` 判断是否已有路线，再结合 query 判断本轮是否需要 CMD。需要执行动作但未闭环时，归因 D4。
- D5：总结文本应直接回答沿途问询，不应空泛复述或表达成已执行改路/导航。
- D6：当路线数据不足、对象不存在或需要用户选择时，应说明限制或给出可行替代；纯事实回答不要求额外补充未询问信息。
