## 场景专属规则

本节只描述 `inquiry.route-info` 相对通用前置规则与全局 D0-D6 规则的补充项；未覆盖项按公共规则判断。

### 场景专属硬条件

- D4: 以 `env` 判断是否已有当前路线：`env` 明确展示当前导航路线时，查询该路线的 ETA、距离、费用、拥堵、道路属性或沿途信息不应发新路线 CMD；`env` 为空或未展示当前导航路线时，若回答 query 必须先计算一条明确新路线，则应有路线计算 CMD。已有路线下出现明确不同目的地，或 query 与当前路线的关系无法从 `env`、query、`tool_calls` 确认时，按证据综合判断，不套用静态结论。`history` 仅用于解释 query 指代，不能推翻 `env` 的路线状态。违反上述要求按 D4 归因。
- D5: 未返回路线属性关键回答或总结文本缺失，按 D5 归因。
- D1: 未识别为路线信息问询，或将 ETA、距离、费用、拥堵、路线比较等问询误处理为导航执行、改路或 POI 搜索，按 D1 失败处理。
- D1: 起点、终点、当前路线、所问属性维度或比较对象识别错误，按 D1 归因，导致答案不可用时判 0 分。
- D3: 路线 ETA、距离、费用、拥堵、推荐理由等结论与 `tool_calls`、`env` 或 `history` 明显不一致，按 D3 归因；编造确定性路线数据时判 0 分。
- D5: 总结文本空泛、答非所问，按 D5 归因。

### 专属维度覆盖

- D1：重点看是否正确识别路线属性问询，并解析起点、终点、当前路线、比较对象和所问属性维度。
- D2：重点看回答是否覆盖用户询问的路线属性，例如 ETA、距离、费用、拥堵时段、推荐路线理由等；起点缺省时需正确继承当前位置或当前路线。
- D3：重点看路线计算、交通预测、费用、距离、时间和推荐理由是否有 `tool_calls`、`env` 或 `history` 证据；不得编造实时或预测数据。
- D4：重点看路线问询是否形成回答闭环；以 `env` 判断是否已有路线，再结合 query 判断本轮是否需要 CMD。用户明确要求执行路线动作时仍需形成执行闭环。
- D5：总结文本应直接回答路线属性问题，表达清楚量化或定性结论，不应泛化推荐或混入无关 POI 信息。
- D6：当路线数据缺失、预测不确定、存在多路线选择或需要用户决策时，应提供必要限制说明、比较信息或替代建议。
