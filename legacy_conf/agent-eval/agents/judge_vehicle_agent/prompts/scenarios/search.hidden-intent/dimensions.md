## 场景专属规则

本节只描述 `search.hidden-intent` 相对全局 D0-D6 与 `search` 场景族规则的专属覆盖；未覆盖项回退到公共规则。

### 场景专属硬条件

- D0: 医院等敏感场景不得替代专业诊疗、给出确定性医疗判断或危险建议；仅推荐就医地点、急救/就医方向等合理安全提示不扣分。
- D1: 主类别识别错误、把隐藏意图理解为其他不相关任务，或对地点、对象、筛选条件、关系约束理解严重偏差，按 D1 失败处理。
- D2: 大部分或全部地点与 query 不相关、地理范围明显错误、限定条件完全未生效、主体与附属关系判断错误，按 D2 失败处理。
- D4: 必须满足当前预期输出形态；工具存在满足主品类及核心约束的有效候选却未输出对应 DTO，搜索未闭环，判 0 分；工具经针对性搜索仍无有效候选，且 Agent 明确披露无结果并给出合理拒答或兜底时，DTO 可为空，D4 判 2 分。`cmd_list` 非空时，由评判者结合用户意图判断 CMD 是否合理：发 CMD 是对 query 意图的合理兑现（如"快没油了"→发起导航去加油站）则不视为误发；用户意图仅为搜索/推荐候选却发起导航等端指令（如"找个附近评分高的川菜馆"→直接导航到某一家），属于误发端指令，按 D4 归因。

### 专属维度覆盖

- D1：必须正确识别隐藏意图并映射到对应 POI 类别，例如“人不太舒服，想去医院看看”→医院，“想去拍个证件照”→照相馆/快印店。；不得停留在字面词解释或泛化成无关任务。
- D2：召回多个地点时，必须评估每个地点与用户起点或当前位置的距离是否合理；明显远离用户且不符合“附近/周边”语义的点视为召回错误。营业状态、评分、价格、设施能力、负向约束、可用性等筛选条件应按工具返回逐项校验。
- D3：POI 名称、地址、评分、营业状态、标签、距离等事实必须来自工具或 DTO 证据；POI 标签必须与用户 query 和工具返回属性一致，不得虚构或编造标签。
- D4：重点看搜索是否形成与候选状态一致的闭环：存在有效候选时应输出对应 DTO；无有效候选且已明确披露并合理拒答时允许 DTO 为空。CMD 是否适当结合用户意图判断。
- D5：总结文本应围绕用户隐含需求给出搜索结果或推荐理由；不得输出与当前搜索无关的信息，不得用容易误导为导航执行的话术。
- D6：需要在工具返回支持范围内提供足够帮助用户判断推荐是否可用的信息；优先关注结果是否匹配隐含需求、地理范围是否合理、可用性状态是否准确。距离、评分、营业状态、推荐理由等信息只在用户显式询问、工具已返回且对当前决策有帮助时作为支撑信息，不要求每个结果都完整具备。推荐了临时性不可用 POI 但未主动告知当前不可用状态时，最高 1 分。
