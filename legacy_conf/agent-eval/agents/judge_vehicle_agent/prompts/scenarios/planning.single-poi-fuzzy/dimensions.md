## 场景专属规则

本节只描述 `planning.single-poi-fuzzy` 相对通用前置规则与全局 D0-D6 规则的补充项；未覆盖项按公共规则判断。

### 场景专属硬条件

- D1: 未识别为单 POI 模糊规划，或将推荐、普通搜索、路线问询、导航执行等任务类型混淆，按 D1 归因。
- D2: query 中的组合、模糊或场景条件未同时作用到目标 POI，例如宠物、儿童、约会、拍照、围炉煮茶、设施能力等，按 D2 归因；核心条件整体未满足时判 0 分。
- D2: 推荐 POI 与主类别、地理范围、可用性状态或关键约束明显不符，导致规划对象不可用时按 D2 判 0 分。
- D4: 必须满足当前预期输出形态；预期规划执行但 `cmd_list` 为空，按 D4 执行闭环失败处理。

### 专属维度覆盖

- D1：重点看是否正确识别单一目标 POI 的模糊规划意图，并将自然语言场景条件拆解为可校验的主类别、属性、设施、状态和空间约束。
- D2：重点看所有组合条件是否同时满足且作用对象正确；不得只命中关键词或主类别，却遗漏用户真正关心的场景适配条件。
- D3：重点看 POI 身份、标签、设施能力、营业/可用状态、距离范围和推荐理由是否有 `cmd_list`、`tool_calls`、`env` 或 `history` 证据。
- D4：重点看是否形成唯一、可执行、动作类型正确的规划闭环；字段错误、漏发、误发或目标对象错误优先归因 D4。
- D5：总结文本应准确概括已满足的关键组合条件和规划对象，避免泛化推荐或让用户误以为未验证的属性已满足。
- D6：当模糊条件无法完全验证、候选存在限制、可用性不足或需要用户选择时，应给出必要限制说明或替代建议；纯执行成功时不要求额外冗余信息。
