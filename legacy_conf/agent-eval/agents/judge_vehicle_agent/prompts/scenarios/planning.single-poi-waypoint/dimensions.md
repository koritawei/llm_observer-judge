## 场景专属规则

`planning.single-poi-waypoint` 为历史 tag 兼容入口，评测规则与 `route-search.along-route` 一致；未覆盖项按公共规则判断。

### 场景专属硬条件

- D4: 先以 `env` 判断是否已有当前路线：`env` 明确展示当前导航路线时，查询该路线的 ETA、距离、费用、拥堵、道路属性或沿途信息不应发新路线 CMD；`env` 为空或未展示当前导航路线时，若回答 query 必须先计算一条明确新路线，则应有路线计算 CMD。已有路线下出现明确不同目的地，或 query 与当前路线的关系无法从 `env`、query、`tool_calls` 确认时，按证据综合判断，不套用静态结论。`history` 仅用于解释 query 指代，不能推翻 `env` 的路线状态。行中，`顺路找个 + POI 类别`视为用户委托完成一个沿途目标：存在满足主品类及核心约束的有效候选时，应输出对应 DTO，并下发唯一且与该目标一致的途经点/导航 CMD；`顺路找 + POI 类别`视为仅搜索或浏览：存在有效候选时应输出 DTO，不得下发 CMD。再按用户是否将候选选择权委托给 Agent 判断 CMD 是否合理：若用户要求完成一个沿途目标、未要求列举或比较候选，即使工具返回多个合理候选，也允许 Agent 选择其中一个并下发与该目标一致的途经点/导航 CMD，不属于误发；若用户要求多个候选、比较、咨询或明确保留选择权，则应先返回候选，未经用户选定直接下发 CMD 属于误发。机场或火车站多候选且未唯一消歧时，按公共候选消歧规则优先追问，不适用上述代选执行。工具经针对性搜索仍无有效候选且已明确拒答时，不要求输出 DTO 或 CMD。
- D1: 未识别为基于当前路线的沿途/顺路搜索，或将沿途搜索、目的地附近搜索、普通导航、路线问询混淆，按 D1 失败处理。
- D2: 沿途 POI 明显偏离主路线、绕行严重、终点/途经点关系错误或原路线被错误覆盖，按 D2 归因；导致路线不可用时判 0 分。
- D2: 绕行评估需量化判定（从 `tool_calls` 或 `cmd_list` 提取绕行距离/时间，无数据时基于 POI 与原路线的空间关系合理推断）：绕行距离 ≤ 3km 且时间 ≤ 5 分钟视为合理；3km~10km 或 5~15 分钟之间视为偏大，按 D2 归因最高只能判 1 分；≥ 10km 或 ≥ 15 分钟视为严重绕行，严重偏离“顺路/沿途”语义，直接按 D2 归因判 0 分。
- D4: 绕行严重导致原路线被错误覆盖，按 D4 归因；工具存在满足主品类及核心约束的有效候选却未输出对应 DTO，搜索未闭环，判 0 分；工具经针对性搜索仍无有效候选，且 Agent 明确披露无结果并给出合理拒答或兜底时，DTO 可为空，D4 判 2 分。

### 专属维度覆盖

- D1：重点看是否正确区分沿途/顺路搜索、目的地附近搜索、路线问询和导航执行；行动类 query 与问询类 query 需按 `env`、query 和候选选择权处理。
- D2：重点看 POI 是否位于当前路线合理范围内，绕行是否可接受，且品牌、服务区、距离、设施、否定/偏好等约束是否同时生效。绕行评估采用与硬条件一致的阈值：≤ 3km/5 分钟合理；3~10km/5~15 分钟偏大（最高 1 分）；≥ 10km/15 分钟为严重绕行（0 分）。
- D3：重点看 POI 身份、位置、绕行信息、可用状态、标签和已采纳约束是否有 `cmd_list`、`tool_calls`、`env` 或 `history` 证据。
- D4：重点看搜索是否形成与候选状态一致的闭环；行中 `顺路找个 + POI 类别` 有有效候选时应输出 DTO 并形成唯一、可执行、动作类型正确的途经点/导航 CMD，`顺路找 + POI 类别` 有有效候选时仅应输出 DTO；机场或火车站多候选未唯一消歧时应追问。无有效候选且已明确披露并合理拒答时允许 DTO 和 CMD 为空。字段错误、漏发、误发优先归因 D4。
- D5：总结文本应明确推荐的是沿途结果，并说明关键约束、可用状态或路线影响，避免表达成目的地附近或已执行未发生的动作。
- D6：存在绕行偏大、无理想候选、临时不可用、约束冲突或需要用户选择时，应给出必要限制说明或替代方案；纯执行成功时不要求额外冗余信息。
