## 全局 D0-D6 评分规则

最终 `score` 仍按 0/1/2 输出；`reasoning` 必须围绕适用维度说明 pass / partial / fail / not_applicable 结论及证据。全局规则提供统一归因口径，具体场景的硬条件、阈值、轮次规则以场景专属规则为准；场景专属的特殊安全边界是在全局 D0 安全底线基础上的补充和收紧，不得替代或降低全局安全底线。

### 总分输出规则

- 0 分：不可用/失败。主要归因维度出现硬失败，或其它适用维度出现导致任务不可用的严重问题，例如安全合规问题、主意图错误、严重事实错误、核心约束失败、CMD 冲突、误发 CMD、漏发必须 CMD、任务闭环失败。
- 1 分：部分可用/有缺陷。主要归因维度未完全满足但未导致任务不可用；或其它适用维度存在明显瑕疵，影响质量但不破坏主任务。
- 2 分：优秀/高质量可直接使用。主要归因维度均满足；其它适用维度无明显失败项，关键证据充分。
- 上述“主要归因维度”的具体取值见本 prompt 后文“场景与预期输出”部分的“主要归因维度”字段，未列入该字段的 D0-D6 维度按“其它适用维度”处理。

### D0 安全与合规

**定义**：评估是否存在安全、合规、危险驾驶、敏感领域越界或明显不适合车机场景的输出。

**通用判分边界**：
- 0 分：触发严重安全或合规问题，直接判 0 分。
- 1 分：表达存在轻微风险提示不足，但不影响当前主任务基本可用。
- 2 分：无安全或合规问题，表达适合车机场景。

### D1 意图识别与任务拆解

**定义**：评估 Agent 是否正确理解用户主意图、子意图、任务类型和当前轮次目标，包括搜索、问询、导航、路线修改、沿途搜索、多轮指代等。

**通用判分边界**：
- 0 分：主意图或任务类型错误，核心对象理解错误，或把搜索/问询/导航/改路等类型严重混淆。
- 1 分：主意图正确，但附加条件、空间关系、偏好/否定条件、动作意图或多轮指代有遗漏。
- 2 分：主意图、子意图、关键对象、约束和上下文指代均理解正确。
- 当当前用户 query 含需上下文消解的指代、承接表达或依赖既有路线状态时，将 `history` 作为理解当前 query 的证据；若 `history` 缺失、无关或不足以唯一消解，应标记为上下文证据不足，不得臆造或强制继承历史信息，也不得仅以此认定 Agent 存在指代理解错误。
- 始终以当前 query 为准：用户已明确给出对象，或明确修改、取消既有意图时，不得强制沿用 `history`；仅在前述需上下文消解的情形下，若 `history` 提供唯一且相关的依据，Agent 应正确解析所指对象、意图或路线状态，误指历史对象、候选或路线状态按 D1 归因。
- Agent 输出的 intent 标签只能为出行/搜索/页内速答/闲聊；标签按用户本轮所需的最终交付对象判定，不由中间使用的工具或数据来源决定：出行表示路线、导航或路线变更；搜索表示查找、比较、推荐或选择 POI；页内速答表示仅依据当前页面已有信息直接回答；闲聊表示直接回答通识、知识或网页查证结论，不交付 POI 推荐/选择结果或车机动作。
- POI 类事实问询可有多种合理 intent：目标是交付 POI 候选、推荐或选择结果时为“搜索”；仅直接回答价格、季节、政策等事实结论时可为“闲聊”；当前页面已有所需信息时可为“页内速答”。
- intent 标签是 D1 的辅助证据，不得仅因其与场景名或工具链路不一致而判失败。仅当实际任务方向、核心对象或回答内容偏离用户所问时，按 D1 判失败；`recommend`、`tool_cmd` 等输出形态是否形成闭环，按 D4 判断。


### D2 需求约束满足度

**定义**：评估显式约束和任务相关隐式约束是否被正确识别、传入、验证并满足，包括地点范围、距离、品类/类型、品牌偏好/排除、营业状态、评分、价格、设施能力、绕行、路线偏好、顺序关系等。

**通用判分边界**：
- 0 分：核心硬约束未满足，推荐或执行结果与关键约束明显冲突，或约束错误导致任务不可用；包括推荐了状态为“不对外开放/疑似关闭/关闭”等永久性不可用的 POI；也包括路线执行结果出现终点丢失、途经点顺序错误、原路线被错误覆盖、沿途结果明显偏离主路线等，导致路线不可用。
- 1 分：任务核心方向和结果仍可用，但任一明确约束未完全满足、仅弱满足、未验证或使用了替代方案；包括主品类与 query 指定类别不匹配但功能相关、推荐指定区域外的 POI、轻度绕路或顺路性不足等。Agent 已披露限制、提供合理替代或请求确认，只表示应对方式合理，不代表原约束已经满足，D2 仍判 1 分。
- 2 分：所有适用约束均被正确识别、验证并实际满足，且体现在推荐结果、CMD 或工具参数中。
- 当当前用户 query 在语义上引用、承接或依赖历史任务（包括显性指代、上下文省略、延续性修改）时，相关的历史地点范围、筛选条件、路线策略、终点/途经点关系及属性问询对象应继续生效，除非用户明确修改或取消；继承错误或约束未落实按 D2 归因，导致当前任务不可用时判 0 分。仅存在 `history` 但当前 query 明确自洽、未语义承接历史任务时，不得将历史约束视为本轮必需约束。
- 临时性/未来性不可用状态需结合 query 判断：若用户明确要求当前营业、当前可用或存在空闲能力，推荐不满足该要求的 POI 属于约束未满足，按结果影响判 1 分或 0 分；若用户未明确要求当前可用，该状态本身不在 D2 扣分，是否主动告知限制及提供替代方案由 D6 判断。永久性不可用仍按 D2 判定。
- 判定“工具返回中存在更匹配约束的候选却未被推荐”时，应先比较候选是否满足 query 的核心硬约束，再比较评分、口碑、距离等质量维度。候选违反其他核心约束或永久不可用时，不属于有效的更优候选；候选满足全部核心硬约束而已推荐项不满足时，不得仅以评分、距离等软质量较差为由认定取舍合理。
- 若全部工具返回中均无候选满足某项明确约束，或满足该项的候选同时违反其他核心约束，Agent 已针对性搜索并明确披露未满足项、提供替代方案或请求确认时，D2 判 1 分；数据覆盖问题由归因链路判断，不得因此将 D2 提升为 2 分。若 Agent 未针对性搜索、未披露限制，或存在同时满足约束的候选却未采用，根据对任务可用性的影响判 1 分或 0 分。

### D3 信息真实性与可信度

**定义**：评估总结文本（`component_text`）、DTO、POI 标签、CMD 或工具参数中的事实是否能被已提供上下文支撑。

**通用判分边界**：
- 0 分：证据完整时，只要存在任意一项可确认的事实虚构或幻觉，即按 D3 失败并判 0 分，不因错误数量少、非核心或主任务仍可用而降为 1 分。以下任一情况均属于虚构或幻觉：事实断言与 `tool_calls`、`cmd_list`、`env`、`history` 或 query 矛盾；确定性断言在完整证据中无来源；引用了错误对象或错误字段；使用了错误计算口径；把其他 POI 的标签、属性或状态嫁接到当前 POI；证据已明确给出相关字段却声称“未提供”“无法确认”或“暂无数据”。多轮场景中，引用的历史对象、属性、状态、路线或已满足条件与 `history`、`tool_calls`、`env` 或 `cmd_list` 不一致，或无证据声称历史条件已满足，也属于事实虚构，直接判 0 分。
- 1 分：不存在事实虚构、幻觉或证据矛盾，所有事实性断言均有证据；但存在非事实性质量缺陷，例如表达泛化、证据对应关系说明不清、遗漏非关键事实，或 POI 标签仅覆盖主类别而未完整覆盖限定条件。确定性事实断言缺少支撑时不得判 1 分。
- 2 分：所有事实性断言均有明确证据，且对象、字段、数值、关系和计算口径正确；POI 标签与 query 及对应 POI 自身属性一致，并覆盖关键筛选条件。
- 重点核验总结文本中的 POI 属性、状态、数值、路线变化、执行动作和跨轮引用，以及 DTO、POI 标签、CMD 对象与参数；逐项与 `query`、`tool_calls`、`cmd_list`、`env`、`history` 核对。
- 具体属性：断言“拍照打卡”“安静”“适合约会”“亲子”等属性时，必须有该 POI 自身的对应或语义等价证据。仅凭“带小院”推断“适合拍照”、凭“环境好”推断“适合约会”等弱相关信息作确定性断言，属于虚构，判 0 分。若使用“可能”“可考虑”等措辞明确表达主观建议或待确认推断，且未表述为已验证事实，可按 1 分处理。把其他 POI 的真实属性安到当前 POI 上属于跨 POI 嫁接，判 0 分。
- 具体数值：距离、时长、相邻节点间隔、累计到达耗时、绕行公里数、ETA、费用、空闲桩数等必须有证据出处。路线距离、耗时、ETA 或费用应优先核对与 Agent 陈述同起终点、同出行方式的 `plan_route`；`search_place` 返回的是候选 POI 距离，不得在存在匹配 `plan_route` 时将其视为冲突证据。允许对同一对象、同一区间、同一口径的证据值进行单位换算、四舍五入、区间化或求和；计算前必须核对对象、路线区间、单位和口径。不得把累计值当作相邻间隔，不得把其他 POI 或其他路段的值用于当前对象。无证据来源，或对象、区间、公式、口径错误，均属于数值事实虚构，判 0 分。DTO 中待核验的数值不能自证，必须回溯 `tool_calls`、`cmd_list`、`env`、`history` 或 query。

### D4 任务落地与执行闭环

**定义**：评估该执行时是否执行、该问询/推荐时是否避免误执行，以及 CMD、工具调用、总结文本是否形成闭环。

**通用判分边界**：
- 0 分：预期必须执行却无 CMD，问询/推荐场景误发 CMD，或 `cmd_list` 中出现端指令冲突。任何场景中，CMD 的执行对象、动作类型或关键参数与用户当前意图及已提供上下文不一致，包括执行错误对象、终点/途经点或顺序错误、错误覆盖路线、未落实用户明确更新，均属于执行闭环失败，判 0 分。工具调用同理：入参违反该工具参数契约（如把「当前终点」等地点字面量填入要求 POI ID 或引用的参数）导致调用失败、用户所问信息因此完全未获有效回答的，同属执行闭环失败，判 0 分；事后如实披露无法获取、未编造结论不改变该定性，仅保证 D3/D5 不追加扣分，不得据此升为 1 分。仅当入参合法而外部数据确实缺失、Agent 如实说明限制时，才属数据缺失兜底而非执行错误；调用成功或参数瑕疵未影响结果可用性的，仍按 1 分“动作不精确”处理。
- 1 分：动作方向正确但关键字段缺失、动作不精确、执行不彻底，或执行结果表达不清。
- 2 分：输出形态、CMD 状态、操作类型、关键参数与用户意图一致。
- 搜索/推荐场景中，工具经过针对性搜索后确实没有满足主品类及核心约束的有效候选，且 Agent 明确披露无结果并给出合理拒答或兜底时，DTO 为空属于正确闭环，D4 判 2 分。若工具中存在有效候选却未输出对应 DTO，属于搜索闭环失败，D4 判 0 分。

### D5 表达与场景适配

**定义**：评估车机场景下的表达是否简洁、可听、可确认，是否准确说明结果、限制、不可用状态或替代方案。

**通用判分边界**：
- 0 分：表达严重误导或无法理解，导致用户无法确认结果或继续操作。
- 1 分：表达基本可用但结构不清、关键说明不足，或与车机场景不够适配。
- 2 分：表达简洁准确，适合车机场景，并支持用户确认或继续决策。

### D6 信息充分性与决策帮助度

**定义**：评估是否在用户需要选择、比较、确认、澄清或风险判断时提供足够信息；不要求纯执行类车机回复额外补充用户未询问的信息。

**通用判分边界**：
- 0 分：在必须澄清或必须告知关键限制时完全缺失信息，导致用户无法判断结果、执行对象或风险是否可用；包括 query 明确询问可用性但所有结果均不满足，且未告知不可用或替代方案。
- 1 分：用户有明确问询/比较/选择需求，或存在需要告知的限制，但回复只给出基础信息，缺少关键决策依据；包括推荐了临时性/未来性不可用的 POI（如“休息中”“已休息”“即将营业”“暂停开放”“暂停营业”“空闲桩数=0”“建设中”“装修中”）但未主动告知当前不可用状态。
- 2 分：在适用 D6 的场景下，提供足够支持用户决策或确认的关键信息；在纯执行类场景中，简洁确认且不冗余也可视为满足或不适用。
- D2 与 D6 分别评价“结果是否满足可用性约束”和“是否充分告知限制”：若 query 明确要求当前营业、当前可用或存在空闲能力，推荐临时性/未来性不可用 POI 按 D2 判定，未主动告知限制或替代方案再按 D6 判定；若 query 未明确要求当前可用，则该状态本身不在 D2 扣分，未主动告知时按 D6 判定。永久性不可用仍按 D2 判定。
